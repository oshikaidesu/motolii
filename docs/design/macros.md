# Macros — ユニバーサル信号モジュレーション設計

## 目的

「初心者向けに機能を削る」のではなく、**普遍的な抽象を 1 つに絞ることで、プロも初心者も同じ道具で意図まで最短距離で通せるモジュレーション機構**をレイヤー単位で提供する。

## コア抽象：入力ソースと出力先の完全直交化

すべての連動は 1 本のパイプに統一する。

```text
[入力ソース (0..1)]  ──▶  [レンジ写像 (Min..Max)]  ──▶  [任意の数値プロパティ]
  Knob / Audio / MIDI       1:N ファンアウト              Transform / Fill / Text /
  Layer / Wave              反転 (Min > Max) 可           Audio / WGSL・ISF・JS エフェクト
```

- **入力側（`macro_sources` + `macro_1..8`）**: 手動ノブ・音声レベル・MIDI ノート・他レイヤーの数値・LFO 波形のいずれも正規化された `0..1` 信号として扱う。
- **出力側（`macro_map`）**: どの数値プロパティを `[Min, Max]` の範囲で動かすかだけを持つ。
- **直交性**: 入力ソースを `Knob` → `Audio` → `Wave` へ差し替えても、下流の接続や `Min..Max` は一切失われない。逆に `Knob` に戻せば元のキーフレームもそのまま残る。

## UI の原則（D&D・Map モード併用・インライン・段階的開示）

1. **近距離は D&D、重ねた FX 跨ぎは `Map` モード（同じ 1 仕組みで 3 速度）**
   - **見えるパラメータ 1 個**: 各スロット右上のプラグ (`○`) をそのまま下の任意パラメータへドラッグ＆ドロップ（0 クリック・最速）。
   - **スクロール先の隠れた FX 1 個**: プラグ (`○`) を 1 回クリックしてアーム → スクロールやカード展開してからパラメータをクリック（接続後に自動解除）。
   - **重ねた FX を跨いで連続接続**: `Map` ボタン ON で連続マッピング状態に入り、スクロール・折りたたみ展開しながら複数パラメータを連続クリックで接続できる（各フィールド右上にも対象スロット `M1` 等を表示するため、`Macros` カードが画面外にスクロールしても迷わない）。`Mappings` 表も自動で開き、再度 `Map` で終了する。
2. **可動域をターゲット側で見せる（インラインレンジ帯）**
   - 接続された数値フィールドの下端に、スロット色の可動域バンド (`Min..Max`) と現在値ピップを直接描く。一覧表を開かなくても「いま誰にどの幅で揺らされているか」が一目で分かる。
3. **詳細設定は必要なときだけ開く**
   - ソース種別とパラメータはスロット左上のバッジからインライン設定トレイを開く。
   - 厳密な数値での `Min` / `Max`・反転 (`⇄`)・解除 (`×`) は `Ranges` トグル、スナップショット呼び出しは `Vars` トグルに畳む。

## 既存機能との境界

### Easing 区間の `Cyclic` との違い

- **Easing の `Cyclic`** は「キーフレーム A → キーフレーム B の 1 区間の中をどう補間するか」というトランジション表現。
- **Macros の `Wave` (LFO)** は以下の点で役割が異なる：
  1. キーフレームを 1 つも打たずに、時間 `at` に沿って連続駆動できる。
  2. 1 つの波から複数パラメータ（複数エフェクト跨ぎを含む）を異なる `Min..Max`・反転込みで同時駆動できる。
  3. 制作途中で「やっぱり音に反応させたい」「手動ノブで決めたい」となったとき、接続を保ったまま `Wave` ⇄ `Audio` ⇄ `Knob` を 1 クリックで入れ替えられる。
- DAW のように「Sin で別の Sin の周波数（Hz）や振れ幅を揺らす」表現とも相性がよく、将来ソース側のパラメータ（Rate / Phase / Gain）を数値プロパティまたは他スロット参照として開放すれば、同じパイプのまま FM 的な重畳へ自然に拡張できる。

### エフェクト・シェーダー側との境界

- エンジン評価は `doc_number()` の 1 箇所のみに集約する（[value_at.cpp](../../engine/document/evaluate/value_at.cpp)）。
- 個別のシェーダー・エフェクト・Transform 評価器はマクロの存在を知る必要がなく、新しく追加された WGSL / ISF / JS エフェクトも自動的にモジュレーション対象になる。
- Audio 解析と MIDI 解析は独自実装を増やさず、エンジン既存のキャッシュ付きリーダー（`sound_of` / `sound_wave` と `midi_of`）をそのまま使う。

## 設計上の不変条件

- **ドキュメント単位で保存**: `macro_map` の `Min`/`Max` はエンジン内部のドキュメント単位で記録し、UI 表示・編集時のみ `propScale` で換算する（解像度や表示単位の変更で値がズレない）。
- **1 プロパティ 1 駆動元**: 同じプロパティに別スロットを接続すると上書きされ、競合する二重駆動を作らない。
- **循環参照の安全停止**: `Layer` ソースが相互参照（A → B → A）になっても、スレッドローカルな再帰深度上限で必ず有限値に収束する。
- **再生時のライブ追従**: `macro_sources` が設定されたレイヤーはキーフレームが無くても再生・スクラブに追従してインスペクターの数値を更新する。
- **キャッシュ整合性**: `macro_map` と `macro_sources` のパース結果は `DocValueCache` に保持し、`doc_forget` / `doc_forget_keys` で必ず破棄する。
