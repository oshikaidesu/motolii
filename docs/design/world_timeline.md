# World Timeline — 舞台装置と演者の分離

> カメラの XYZ を指定して向きを指定して…は、右足と左足をコントローラーで操作しているようなもの。
> 歩くときに膝の角度は考えない。「あそこに行く」と思うだけ。

## 問題

コンポジットソフトのカメラは 6 自由度（位置 XYZ + 回転 XYZ）を全部ユーザーに触らせる。これは歩行シミュレーション。映画のカメラマンは XYZ なんか口にしない。「あの人を撮る」「次はこっちに寄る」。対象と距離感だけで会話する。

AE にカメラが入ったのは CS3（2007）。それまで 15 年間カメラなしでやっていた。後付けだから扱いが雑。一方ゲームエンジンはカメラに命をかけている。プレイヤーの体験の 100% がカメラ越しに届くから。Unity Cinemachine（2017）、Unreal Sequencer、God of War（2018）のワンカット。コンポジットソフトのカメラは 15 年遅れている。

## 3D カメラ操作の歴史 — 3 つの道

| 方式 | 代表 | やっていること |
|------|------|--------------|
| 自由を全部渡す | マリオ 64（1996） | カメラ事故だらけ。歩行シミュレーション |
| 自由を全部取り上げる | クラッシュ（1996）、バイオ、旧 GoW | 安定するがユーザーは操り人形 |
| **意図だけ受け取る** | **ゼルダ Z 注目（1998）** | ボタン 1 つで 6 自由度が消える |

ゼルダ以後の発展：
- **ロックオン継承型** — デビルメイクライ、ダークソウル。Z 注目を戦闘特化に進化
- **固定カメラ回帰型** — 旧 God of War。映画的構図を優先
- **意図読み取り型** — God of War（2018）。ロックオンボタンすら無くし、スティックの向き＝意図として読み取る

Motolii が学ぶべきは操作方法ではなく**意図の圧縮の仕方**。ゲームのカメラはライブ操作（右スティック）で、タイムライン（事前に記録する）と合わない。Motolii 版の意図圧縮は「**この時間に何を見せたいか**」。

## 解法：World Timeline タブ

タイムラインに 2 つのタブ。ルーラー（時間軸）は共有、中身は別世界。

### WORLD タブ — 舞台装置

```
 ── WORLD ──────────────────────────────────────
 SCENE      │ [===屋上===|=スタジオ=|==屋上==]
 CAMERA     │ ┌──┐┌──┐ ░░░░░░░░░░ ┌──┐┌──┐
            │ │画││画│ f(beat)    │画││画│
 L1 Light   │ ━━━◆━━━━━━━━━◆━━━━━━━━━━━━━━
 H1 HDR     │ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 AUDIO      │ ♪━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### LAYERS タブ — 演者

```
 ── LAYERS ─────────────────────────────────────
 背景       │ ━━━━━━━━━━━━━━━━━━━━━━   屋上
 タイトル    │ ━━━━━━━━━━━━━━━━━━━━━━   ALL
```

## フィルムストリップカメラ

カメラのキーフレームが数値ではなくサムネイル。**逆運動学（IK）** と同じ構造。

- アニメーション IK：「手をここに」→ 肘と肩を逆算
- カメラ IK：「**この画が欲しい**」→ 位置・向き・距離を逆算

### パシャ操作

ステージ上で構図を決めて「パシャ」→ コマとして記録。

1. ステージを好きな構図にする
2. 「パシャ」を押す
3. 今の画がフィルムストリップのコマになる
4. 時間をずらして次の構図を作って「パシャ」
5. コマとコマの間はシステムが補間する

**絵コンテ＝キーフレーム。** 映像制作は絵コンテから始まる。なのにコンポジットソフトに来た瞬間、絵コンテで 10 秒で描けた構図を XYZ 手打ちで 30 分かけて再現する。フィルムストリップカメラはこの断絶を埋める。

```
絵コンテ → [コマ1][コマ2][コマ3] → 完成映像
              ↑ ここが Motolii
```

### UI モチーフ：写真フィルム

物理フィルムの情報構造がそのまま使える：

- **コマ** → カメラキーフレームのサムネイル
- **コマとコマの間** → 補間区間（`~~~` = 滑らか、隙間なし = ハードカット）
- **パーフォレーション** → タイムラインの目盛り

普通のタイムラインはキーフレームが「点」で間が「カーブ」。フィルムストリップだとキーフレームが「面」。サムネイルが面積を持つから、何が起きるか見える。スイス・パンクとも合う。グリッド、ベタ面、強いフレーム。

### コマの中身

- 通常：スナップショット（パシャ時の静止画を保存）
- ホバー時：拡大＋自動算出値（距離、FOV。触らなくていいが触れる）
- レイヤー変更後：「再撮影しますか？」

```
  ┌──────────┐
  │//////////│
  │// 画   //│  ← サムネイル拡大
  │//////////│
  ├──────────┤
  │ 距離 1200│  ← 普段は隠れてる
  │ FOV  35mm│
  │ [再撮影] │
  └──────────┘
```

## SCENE 行 — コンポジションの消滅

MV は映像がぶつ切りで音楽が一本。サビで全然違うシーンに飛ぶ。カメラの補間が通用しない。

SCENE 行はレイヤーのスコープ。各レイヤーがどのシーンに属するかタグを持つ。

```
 SCENE      │ [===屋上===|=スタジオ=|==屋上==]
```

SCENE が「屋上」の区間では屋上タグのレイヤーだけが映る。CAMERA のコマは SCENE の中でアングルを切り替える。

- **シーン（場所）** → 3〜5 個。レイヤーのスコープ
- **カット（アングル）** → 何個でもいい。フィルムストリップのコマ

AE のプリコンプは「別の部屋に持っていく」。Motolii の SCENE は「同じ部屋にいるけどカメラに映るかどうかだけ変わる」。レイヤー間の参照関係が壊れない。ALL タグのレイヤー（歌詞テロップ等）は常に映る。

**コンポジションという概念が消える。** 全部 1 つのタイムライン上で完結。MV で 20 シーンあっても 1 画面。音は切れない。

## 手動 / 式 / 混在

各行がフィルムストリップ（手動）とエクスプレッション（式）を区間ごとに切り替えられる。

```
 CAMERA     │ ┌──┐┌──┐ ░░░░░░░░░░ ┌──┐┌──┐
            │ │画││画│ f(beat)    │画││画│
            │  手動     式          手動
```

- A メロは手でコマを並べる
- サビは `random(scene, beat)` で回す

SCENE 行も式で回せる：`scene = ["屋上", "スタジオ", "街"][floor(beat % 3)]`

既存の式カード（`shelves/` の JS）と同じ仕組み。カメラ用に新しいインフラは要らない。

映画的なカメラワークも、BPM に合わせて暴れる実験的 MV も、同じ 1 画面で作れる。

## ワークフロー

### Phase 1：絵コンテ（WORLD タブ）
- レイヤーを置く（まだアニメーションなし）
- WORLD タブで構図を決めて「パシャ」→ コマになる
- 時間をずらして「パシャ」→ 次のコマ
- **この時点でカメラワークのプレビューが見られる**

### Phase 2：演出（LAYERS タブ）
- レイヤーのアニメーションを付ける
- カメラはフィルムストリップに従って自動で動く
- 必要なら WORLD タブに戻ってコマを微調整

業界のワークフロー（絵コンテ → レイアウト → アニメーション → カメラ → コンポジット）の最初の 3 ステップが 1 つに潰れる。

## camera_target_mode.md との関係

[camera_target_mode.md](camera_target_mode.md) のターゲットモードは「パシャ」の下位互換。ターゲットモードは「何を見るか」を選ぶ。フィルムストリップは「どう見えるか」を直接指定する。ターゲットモードはフィルムストリップの裏側で動く仕組み（ターゲットレイヤーに向けてカメラ位置を逆算する）として統合できる。
