# UAT シナリオ

製品として出す前に、使う人の手で通す操作。After Effects・Alight Motion を使う人が「当たり前」と思ってやることを並べる。各行は、使う人がすることと、使う人に見える結果だけを書く。

## 通るかどうか

ここには書かない。行が通るのは、次のどちらかの時だけ。

- その行のテスト `app/test/uat/uat_<番号>_test.dart` が、エンジンを組んだ機械で通る（`cd app && flutter test --tags uat`）。飛ばされたテストは通らない扱い。
- プログラムで確かめられない部分は、[uat_audit.md](uat_audit.md) で監査役が「通る」とした。

どちらも無い行は、通らない。テストは行の言葉だけを渡された書き手（`.claude/agents/uat-test-writer.md`）が書き、main に入ったら凍る。直せるのは作者だけ（`.claude/hooks/uat_lock.py`）。

## 7. 物理演算（Newton 型）

AE の物理プラグイン [Newton](https://aescripts.com/newton/) でよく作られるもの：タイトルやロゴが落ちて積もる、玉がぶつかって積み木が崩れる、無重力での衝突、器に注いで満たして流す、紐やジョイントでつなぐ。

Newton の体の種類：Dynamic（重力で落ちる）・Dormant（触られるまで止まる）・Static（動かない）・Kinematic／AEmatic（キーフレームどおりに動いて他を押す）。値：Density・Friction・Bounciness・Mesh precision（丸が丸いまま当たる）。結果はキーフレームとして書き出される（[PremiumBeat の解説](https://www.premiumbeat.com/blog/after-effects-newton-3-plugin)）。

Motolii の物理は Jolt Physics で、2D は Jolt 自身の `EAllowedDOFs::Plane2D`（`engine/community/jolt/rigid_bodies.h`）。棚は `shelves/expressions/rigid_body.js`（Mass・Gravity・Bounciness・Friction、値は Jolt のまま）。1 役目 1 ライブラリなので、2D 用に Box2D を足さず、足りない物は Jolt にある物で埋める。

## 8. ブロブトラッキング（Tracery 型）

AE の Tracery（aescripts）は、色を手がかりに動画の中の塊を追い、その上に HUD を重ねる。公式の説明は「色で物を追い、飾りを重ねる」だけなので、枠の形・つなぐ線・ラベルは、同じ種類の道具（Blob Tracker、Machine Vision）の説明から補った。

Motolii では、ネットにあるブロブトラッキングのコード（p5.js のスケッチ、シェーダー）を動画にそのまま貼って使う。p5.js のスケッチは、下にある動画を `createCapture`・`createVideo` で受け取り、`get()` と `pixels` で読める（`engine/community/p5/p5_stand.h:208`）。動画は CPU で小さい寸法にして読まれる（`engine/media/video_frames_for_scripts.h`）。

## 9. 光とプリズムの過剰な MV

光を何重にも重ねる MV。AE ではよく次の物で作られる。
- Deep Glow：物理的に広がるグロー。グローの元の色を分ける色収差が付いている。
- Sapphire の Distort Chroma：ガラスのプリズム越しに見たような分光。
- Spotlight FX の Prism Effects：虹の屈折・色収差・光の分散のプリセット。
- レンズフレアやライトリークの素材を重ねる。

Motolii の棚に、この種の光はほぼ揃っている。
- 色のずれ：`effects/stylize/am_rgbsplit.wgsl`、`effects/glitch/rgbshift.wgsl`、`effects/glitch/chroma.wgsl`
- グロー：`stylize/sl_bloom.wgsl`、`stylize/Bloom.fs`、`stylize/Glow-Fast.fs`、`looks/Light Glow.motolii` ほか
- 光：`stylize/am_lensflare.wgsl`、`stylize/sl_flares.wgsl`、`stylize/Lens Flare.fs`、`stylize/am_rays.wgsl`、`stylize/am_radialrays.wgsl`、`stylize/v002 Light Leak.fs`、`looks/` の Streaks
- 画面を割る：`move/am_kaleidoscope.wgsl`、`move/am_mirror.wgsl`
- 拍の演出：`create/over_footage/white_flash.js`、`color/Strobe.fs`、`color/RGB Strobe.fs`、`move/am_autoshake.am`

プリズムのガラスは `engine/materials/thick_glass.mat` にある。波長ごとに屈折率を変えて虹に分ける。式は Saqoosha の Spectral-Glass（MIT、glTF の KHR_materials_dispersion と同じ Cauchy とアッベ数）で、`split` が色の分かれ方を決める。

## 13. 起動画面と書き出しパネル

**起動画面の理想**：前の続きが一目で分かり、1 回で戻れる。過去のプロジェクトは最後に見ていたコマのサムネイルで並ぶ。新しく始める時は、そこで縦横（横 16:9・縦 9:16・正方形）を選べる。ファイルを落とせば、その素材で始まる。

**書き出しパネルの理想**：「どこに出すか」（YouTube・ショート・透過素材・GIF・連番 PNG・自分で決める）を選ぶと、寸法・形式・音が決まる。細かい項目は畳んで残す。書き出す前に大きさと時間の目安が出る。出ている間は進み具合と残り時間が見え、やめられる。終わったら Finder で開け、点滅の検査の結果もパネルに出る。

今のホームは CapCut のデスクトップ版にならったサムネイルの一覧で、日付ごとにまとめ、検索・並べ替え・選択・複製・ゴミ箱がある（`app/lib/workspace/window/home.dart:3`）。サムネイル・寸法・長さは、プロジェクトを開かずに最後の保存から読む。大きさの書き方は AbsentMotion（Apache-2.0）の `formatBytes` に従う。

今の書き出しは、上のバーの Render から開く小さいパネル（`app/lib/workspace/top_bar/render_button.dart`）。名前・Resolution・Rate・Quality・Motion blur・Background を選び、形式は MP4・HEVC・GIF・PNG・JPEG。設定は Alight Motion と同じくプロジェクトに残る。

## 15. 右クリックのメニュー

**理想**：Mac の普通のメニューと同じに振る舞う。外を押すと閉じ、その 1 回は下の物に効かない。Esc で閉じる。マウスの位置に開き、画面の端では内側に折り返す。矢印キーで動き、Return で決まる。まだ選んでいない物を右クリックすると先にそれが選ばれ、選んでいる物の 1 つを右クリックすると、選んでいる全部に効く。メニューは 1 つしか開かない。

今のメニューは `app/lib/widgets/context_menu.dart`（Flutter の `RawMenuAnchor`）。閉じるのは `app/lib/widgets/dismiss_region.dart`（Flutter の `TapRegion`）。

## 19. ステージとカメラビューを同時に見る

**理想**：カメラから見た完成の絵と、作業用の自由な視点のステージを同時に見ながら作れる（After Effects の 2 画面、Blender の複数のビューポート）。どちらで動かしても、両方が同じコマで動く。カメラビューは別の窓にして、別のモニターに全画面で出せる。2 つ目を開いても、シーンの計算は 1 回で、描くのだけがビューの数だけ増える。隠れているビューは描かない。重い時は作業用のビューから粗くし、完成の絵は守る。

今のカメラビューは、アプリの窓の中のタブ（`app/lib/workspace/stage/stage_camera.dart`、AE の 2 画面・アクティブカメラにならった、見るだけの画面）。タブが開いているかをエンジンに伝え、閉じていれば描かない（`stage_camera.dart:28`）。エンジンは、作業用カメラでステージを見ている時、同じ時刻のシーンを作品のカメラでもう一度計算して描く（`engine/entry/render_thread.cpp:34`）。

Filament は、1 つのシーン（`Scene`）を、カメラの違う複数のビュー（`View`）で描ける。計算を 1 回にするには、それに任せる。

## 26. フォントの棚：書体はそれぞれの言語で出る

理想：Fonts の棚では、どの書体も、その書体が作られた言語の見本で出る。日本語の書体は日本語、ハングルはハングル、簡体字の書体は簡体字、アラビア文字はアラビア文字（右から左）、欧文は欧文。どの言語向けかは、書体のファイル自身が言っている事から読む。読む先は `meta` 表の `dlng`（作った言語）と `slng`（使える言語）、OS/2 表のコードページ、`name` 表の見本の文（ID 19）。macOS の Font Book と Google Fonts と同じやり方で、持っている字から当て推量しない。名前は書体の `name` 表の名前を、使う人の言語で出す。自分で打った文で、全部の見本を差し替えられる。

今：見本は Google Fonts の gflanguages の見本の表（`engine/third_party/gflanguages/samples.json`、156 の文字の見本）から選ぶ。仕組みはあるが、選ぶ順が逆になっている。
- 1 本ずつ「`Motion for more relations`（Latin）、それから表の順」に試し、最初に全部の字を組めた見本を使う（`fonts_controller.dart` の `read`、`settingFirst`）。
- 日本語・韓国語・中国語の書体はほぼ全部 Latin の字も持つので、Latin が先に通り、英語で出る。各言語の見本が出るのは、Latin の字を持たない書体だけ。
- 書体のファイルが言う言語は読んでいない。持っている字（cmap）だけで決めている。

直し方：言語は書体のファイルから読む。外の実装に任せ、自前の表読みは書かない。
- macOS：CoreText の `CTFontCopySupportedLanguages` と `CTFontCopyLocalizedName`
- Windows：DirectWrite
- Linux：fontconfig の `lang`
- `dlng`・`slng` を読むなら HarfBuzz の `hb_ot_meta_get_entry_tags`

## 33. 選べる物は全部、複数選んでまとめて掛けられる

AE の古い作り（キーの右クリックのキーフレームアシスタント、F9、コンポとレイヤーの 2 段のモーションブラーのスイッチ）は移さない。代わりに、Finder・Figma・Live で誰もが当たり前と思う形を全部に通す。

理想：
- 選べる物は、どれでも ⌘ クリックで 1 つずつ足し、⇧ クリックで間をまとめて取り、空いた所からの囲みで取れる。⌘A で、今いる場所の全部が取れる。
- 選んだ全部に、1 つにするのと同じ操作（値を変える、掛ける、消す、写す、動かす、オン・オフ）が 1 回で掛かり、取り消しも 1 回で戻る。
- 選んだ物で値が違う所は「—」と出て、打てば全部がその値になる（Figma・AE と同じ）。

今あるもの：

## 38. エフェクトを重ねても重くならない

メモリの「重い物を測らない」に従い、時間は測らず、作りが軽いかで見る。

理想：
- 1 枚のレイヤーにエフェクトを 10 枚重ねても、古い PC で 60fps のまま再生できる。増える手間は、重ねた枚数ではなく、本当に要る分だけ。
- 1 ピクセルずつで済むエフェクト（色・トーン・グラデーションマップなど）は、重ねても 1 回の描画にまとめる。まとめるのは、借りた中間表現（TSL のノード）を 1 回で組む形で、自前のコンパイラは作らない（メモリの「TSL を中間表現に」）。
- オフ・量 0・画面の外のエフェクトは描かない。動かないエフェクトは前のコマを使い回し、止めている時に何も変わらなければ描き直さない。
- 重い所だけ、プレビューの解像度を落とせる。書き出しは落とさない。

今あるもの（`stage/layer_effects/`、Filament の `samples/rendertarget.cpp` の形）：
- エフェクトのあるレイヤーは、1 枚だけで画面外の絵に描き、2 枚の絵を交互に使って（ピンポン）エフェクトを順に掛ける（`thing_effects_draw`）。重ねる枚数が増えても、使う絵は 2 枚のまま。
- 途中の絵は、レイヤーの箱（はみ出す分の余白込み）の大きさで、プレビューの画素の細かさ（`ppp`）で描く（`layer_fx_place.cpp`）。画面全体でも、プロジェクトの大きさでもない。
- エフェクトの並びと材料を組むのは、並びが変わった時だけ（`thing_effects`）。オフのエフェクトは並びから外れる（`fx_list.cpp` の `fx_off`）。
- 掛ける前に sRGB へ、掛けた後に線形へ、色の変換を 1 回ずつする（`screen_tone`）。
