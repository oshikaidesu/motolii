# カメラターゲットモード — ゼルダ Z 注目の水平思考

> 枯れた技術の水平思考（横井軍平）：ゲームで 30 年解かれてきた「3D 空間でのカメラ制御」の解法を、コンポジットソフトに持ち込む。

## 原点：ゼルダの Z 注目が解いた問題

3D ゲームのカメラは本来 6 自由度（位置 XYZ + 回転 XYZ）ある。ユーザーに全部触らせると破綻する。ゼルダが出した答え：

1. **ターゲットを 1 つ選ぶ** — 最も近くて向いているもの
2. **カメラが自動で追従** — 距離・高さ・回り込みは自動計算
3. **ユーザーの操作は「次のターゲット」と「外す」だけ**

6 自由度を「誰を見るか」の 1 変数に圧縮した。

## Motolii に持ち込むと

### コンポジットでの「注目対象」= ギズモ

ゼルダでは敵やオブジェクトが注目対象。Motolii では **レイヤーのギズモ**（ステージ上の選択ハンドル、バウンディングボックス）がそれに当たる。

ユーザーの操作：
1. **カメラモードに入る**（ショートカット or ツールバー）
2. **ギズモを右クリック or ショートカット+クリック** → そのレイヤーが **ターゲット** になる
3. ターゲットがキーフレームになる — 「今の位置からそこまでの動き」が自動算出
4. 次のギズモをクリック → 次のターゲット → 間の動きが自動で繋がる
5. 外す → 自由カメラに戻る

### ゼルダとの対応表

| ゼルダ | Motolii |
|-------|---------|
| 敵・オブジェクト | レイヤーのギズモ |
| Z ボタン | 右クリック or ショートカットキー |
| 注目ロック | ターゲットキーフレーム自動生成 |
| スティックで回り込み | ドラッグでアングル微調整 |
| Z を離す | Escape or 再クリックで自由カメラ |
| 次の敵に切り替え | 別のギズモをクリック |

## ターゲットの仕組み

### ターゲット = 「この時間にこのレイヤーを見る」

ターゲットを設定すると、エンジンが自動で算出するもの：
- **カメラの向き** — ターゲットレイヤーの中心を向く
- **カメラの距離** — レイヤーの大きさに応じてフレーム内に収まる距離
- **カメラの移動パス** — 前のターゲットから今のターゲットへの滑らかな経路

ユーザーが追加で触れるもの（ゼルダの「スティックで回り込み」に相当）：
- **オフセット** — ターゲットの真正面じゃなく、少しずらす（ルック方向のオフセット）
- **回り込み角度** — ターゲットの横や上から見る
- **距離** — 寄りと引きの調整
- **タイミング** — いつそのターゲットに到達するか（キーフレームの位置）

### 自動算出の中身

```
前のターゲット → 今のターゲット の間:
  - 位置: ベジエ補間（急な動きにならないよう）
  - 回転: 球面線形補間（slerp）
  - 距離: 対数補間（近づくときスムーズ）
  - FOV: ターゲットの大きさに応じて微調整（任意）
```

ゼルダのカメラが「敵の周りを滑らかに回る」のと同じ原理。

## ユーザーの割り込み

ゲームのカメラが優れているのは、**自動追従中でもユーザーが自由に操作できる**こと。

Motolii でも：
- ターゲット間の補間中、**ドラッグでアングルを変えられる**
- 変えた角度は「オフセット」としてキーフレームに記録される
- 完全に自由にしたければ Escape でターゲットを外す
- 外した後もカメラ位置はそのまま残る（ゲームで Z を離してもカメラが飛ばないのと同じ）

```
[ターゲット A] ──自動補間──→ [ユーザーが割り込んでアングル変更] ──自動補間──→ [ターゲット B]
                              ↑ このオフセットがキーフレームとして残る
```

## インスペクターのターゲットカード

ターゲットが設定されると、インスペクターに **ターゲットカード** が動的に出現する。

```
┌─────────────────────────────────┐
│ ● Target: "タイトルテキスト"      │  ← ターゲットのレイヤー名
│   距離    1200 px               │  ← 自動算出、ドラッグで変更可
│   オフセット  X: +50  Y: -20    │  ← 真正面からのずれ
│   回り込み    15°               │  ← 周回角度
│   到達      1:03:15             │  ← いつ到達するか
│   イージング  ease-out           │  ← 前のターゲットからの補間
│                     [× 外す]   │
└─────────────────────────────────┘
```

- ターゲットがないときはカードが消える（Values Card だけが残る）
- 複数ターゲットを時系列に設定した場合、**最後のターゲットのカード** が表示される
- カード上の値を変えるとリアルタイムでステージに反映

## タイムラインとの連携

ターゲットはタイムラインにも視覚的に現れる：

```
カメラ行: ──●──────────●────────●──→
           ↑          ↑        ↑
        Target A   Target B  Target C
        "背景"     "タイトル"  "人物"
```

- 各ターゲットは **カメラキーフレームのグループ** として記録される
- ターゲット間の補間カーブはイージングで制御
- ターゲットのキーフレームをドラッグすればタイミングを変更

## ゼルダの注目選択ロジック → Motolii 版

ゼルダの「最も近くて向いているもの」を Motolii に翻訳すると：

**カメラモード中にクリックしなくても候補を示す：**
1. カメラの向きの延長線上にあるレイヤーをハイライト
2. 最も近い（画面上の距離が近い）レイヤーを **候補ターゲット** として薄くマーク
3. クリックで確定

これは「Z ボタンを押す前から、次の注目対象が見えている」ゲームの UI と同じ。

## なぜこれが効くか

### 従来のカメラ UI の問題
- 6 自由度を **全部ユーザーに触らせる** — 位置 XYZ、回転 XYZ、FOV、DOF...
- キーフレームを **手で打つ** — 移動先の位置を数値で指定
- 結果が **見えるのは再生してから** — トライ＆エラーが多い

### ターゲットモードが解く問題
- 「**何を見たいか**」だけ選ぶ — 位置と回転は自動
- キーフレームは **対象を選んだ瞬間に生まれる** — 手打ち不要
- **設定した瞬間にプレビューが見える** — ドラッグで微調整すればリアルタイムに反映

### ゲームで証明済み
- Z 注目は 1998 年の時のオカリナから **28 年間** 使われ続けている
- God of War、Dark Souls、モンハン、全部同じ原理
- 「ターゲットを選ぶ → カメラが自動で追従」は人間にとって自然

## 段階的な実装

### Phase 1: 基本ターゲット
- カメラモード ON → ギズモ右クリックでターゲット設定
- カメラが自動でターゲットを向く（Look-at）
- 距離は自動算出（レイヤーがフレームの 60% を占める位置）
- Escape でターゲット解除
- インスペクターにターゲットカード表示

### Phase 2: ターゲット連鎖
- 複数ターゲットを時系列に設定
- ターゲット間の自動補間（位置・回転・距離）
- タイムラインにターゲットキーフレーム表示
- イージング設定

### Phase 3: 割り込みと微調整
- ターゲット中のドラッグでオフセット・回り込み
- オフセットのキーフレーム記録
- ターゲット候補のハイライト（Z 注目のロックオン予告）

### Phase 4: 高度な連携
- ターゲットの追従（移動するレイヤーを追い続ける）
- ターゲットグループ（複数レイヤーを同時にフレーム内に収める）
- 自動的なカメラシェイク（移動速度に応じた微振動）

## 既存概念との関係

| 概念 | 関係 |
|------|------|
| AE の 2 ノードカメラ | ターゲット = Point of Interest。だが AE は位置を手動で打つ |
| Blender Track To | ターゲット追従。だがコンストレイント設定が手間 |
| Unity Cinemachine | 最も近い。Virtual Camera + Follow + LookAt。だが UI がプログラマ向け |
| C4D Target タグ | ターゲット指定。だが自動距離調整がない |
| **ゼルダ Z 注目** | **全部入り：選択・追従・距離・回り込み・割り込み・解除** |

ゼルダが特別なのは、これらを **ボタン 1 つ** に圧縮したこと。Motolii のターゲットモードも、**右クリック 1 つ** に圧縮することで同じ体験を作れる。

## 技術メモ

- エンジン側: `doc_look_at(layer, target_layer)` + `doc_auto_distance(layer, target_layer)` の追加
- 補間: 既存の `slide_keys` バッチが使える。ターゲットの位置・回転・距離を一括キーフレーム
- ギズモ: 既存の `doc_gizmo` + `bounds` データでターゲット候補のヒットテスト
- カード: 既存の Values Card の動的表示（`inspector_values.dart` のカード出し入れ）と同じ仕組み
