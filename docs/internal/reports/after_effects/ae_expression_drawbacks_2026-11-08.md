# After Effects の式の欠点（2026-11-08）

記憶から書いた。Adobe の公式（https://ae-expressions.docsforadobe.dev/）とも実機とも、まだ照合していない。「全て」ではなく、自信のあるものだけ。

- ◎＝仕様か、よく知られた挙動で確度が高い
- ○＝向きは確かだが、細部の記憶が曖昧

## 画面

1. 式が隠れる。目印はストップウォッチの強調と `=` スイッチ程度。中身は行を開くまで見えない（`EE` で全部開く）。◎
2. 式が値を上書きする。式のある値を画面でドラッグしても戻される。キーを触っても見た目が変わらない。◎
3. 式の結果は編集できない。グラフエディタの「式適用後のグラフ」は見るだけ。キーにするには Convert Expression to Keyframes（コマ単位の焼き込み、式には戻れない）。◎
4. 値どうしのつながりが画面に出ない。標準では、式がどの値を読むかの線が無い。◎

## 書く・直す道具

5. エディタが弱い（色分け・補完・複数行）。後年改善されたが時期は記憶が曖昧。◎（改善の時期は○）
6. デバッガが無い。ブレークポイントも `console` も無い。値を確かめるにはテキストレイヤーに出す。現行版の細部は○。
7. エラーが遠い。画面下の帯と黄色い⚠が出て、式は黙って無効になり、値は式なしに戻って絵が変わる。◎
8. プロジェクト全体の式を横断して検索・置換できない。式を保存して貼るパネルがサードパーティで成り立っている（reports/after_effects/ae_panels_lang/ja.md:39）。◎

## 名前

9. 名前で参照する。`thisComp.layer("名前")`、`effect("名前")("名前")`。変更・重複・書き違いで壊れる。名前変更への追従の範囲は記憶が曖昧。◎（追従の範囲は○）
10. 表示言語に引きずられる。日本語版の pick whip は `effect("スライダー制御")` のような言語依存の名前を作り、別の言語の AE に持って行くと壊れる、という既知の問題があった。現行版の状態は○。
11. 式の中の名前が画面の名前と違う（`transform.position`、番号で呼ぶ `(1)`）。◎

## 言語と実行

12. エンジンが2つ。古い ExtendScript 系は `let`・アロー関数が無い。新しいのは V8 の JavaScript。プロジェクトごとの設定で、ネットの式が片方で動かない。◎
13. 配列の演算が特別扱い。`[1,2]+[3,4]` が要素ごとの足し算になる（標準の JS ではない）。QuickJS-ng では文字列になった（commit f3b7e30de）。◎
14. 次元が合わないとエラー。`Expression result must be of dimension 2, not 3`（2D/3D、位置の軸分離）。◎
15. 単位がばらばら。位置はピクセルで y が下向き、回転は度、不透明度は 0〜100、スケールは %、時間は秒。◎
16. `time` はコンポの時間。プリコンプ・タイムリマップ・レイヤーの移動で思った時間にならず、`inPoint`・`startTime` で自分で補う。◎
17. 置き場所で使える語が変わる。`textIndex`・`textTotal`・`selectorValue` は、テキストの Animator の式セレクターの中だけ。◎
18. 乱数が再現できない。`random`・`wiggle` の並びは AE 内部の種で決まり、AE の外で同じ並びは出せない（engine/community/after_effects/ae_expr.h:14）。同じ式がレイヤーごとに違う値になるかどうかは記憶が曖昧。◎（レイヤーごとの差は○）
19. 重くなる。毎コマ・値ごとに評価され、`valueAtTime` の多用や全レイヤーの走査で急に重い。どの式が重いかを測る道具の有無は○。◎

## 作る・使い回す

20. 部品化できない。関数をプロジェクトで共有する仕組みが無く、各値に貼り直す。回避策の `eval`（テキストレイヤー・.jsx）は遅く壊れやすい。◎
21. つまみが回り道。Slider Control などのエフェクトを Null に足して pick whip で結ぶ。つまみに名前・範囲・見た目を持たせられない。◎
22. 差分も grep もできない。式の入ったプロジェクトは .aep（バイナリ）。XML の .aepx はあるが日常では使わない。◎

## 根本

**タイムラインのキーフレームの行に、式が隠れる。**（ユーザの一言、2026-11-08）

式は、キーフレームと同じ行（ストップウォッチ）の裏にしまわれる。行を開くまで見えず、一覧にも出ない。

22 個を分けると次の通り。最初の版は「9 個が同じ原因」と書いたが、名前の問題を混ぜていたので分け直した。

- 隠れる、から出る（7 個）：1・2・3・4・8・20・22。見えない、値を上書きする、結果を直せない、つながりが見えない、探せない、部品にできない、差分が取れない。
- 名前で読む、から出る（4 個）：9・10・11・21。レイヤー名やスライダー名の文字で指すので、名前を変えると壊れ、つまみは Null に足すスライダーで代用する。
- 道具が弱い（3 個）：5・6・7。
- AE の方言（8 個）：12〜19。貼った文面をそのまま通す以上、方言の翻訳は通す側の負担（engine/community/after_effects/ae_expr.h が 12・13・15 の一部を受け持つ。17・18 は未対応か別物）。

先例：Cavalry の JavaScript layer は、式が自分の層で、接続が実物（https://cavalry.studio/docs/nodes/general/javascript-layers/ ）。Motolii のレシピは先頭の `--track@名前:...` で読むつまみを書いている（shelves/create/copies/ae_ring.js）が、AE の文面からは手で書いている。

## 要件（ユーザの言葉のまま、2026-11-09）

> createのリピーターは｢エクスプレッション｣の延長だ
> だから詳細パネルを開くと、中のコードを見れないとおかしい、そして簡略化コードの｢ブロック｣これは構造を簡略化してd&dでプログラミングできるようにしたもの
> シンプルなテキストの｢コード｣
> この2つのモード
>
> ここでノブを明示的にする、もしくはabletonのマクロのようにノブを設定するとプログラムを内部のコード見ずに上からその中身だけを享受できる

### 今の画面との差（2026-11-09 時点のコード）

- Create の Repeater タイルは、物に `shelves/create/copies/repeater.js` を付けて、ノブ（js_StepX・js_Size）を渡すだけ（skin/book/lib/workspace/dock_make_2.dart:419, 488, 503）。
- Inspector に出るのは「Script」カードで、ノブの列だけ（skin/book/lib/sets/inspector/inspector_panel.dart:27 の `ValuesCard`）。中のコードは出ない。
- 「ブロック」と「コード」の2つのモードは、どちらも無い。
- アプリのどこにも、レシピのコードの文字を出す所が無い。Program の棚（skin/book/lib/workspace/dock_program.dart）は、ファイルの一覧・物への付け外し・名前の変更だけ。
- 「Repeater」という名前のカード（skin/book/lib/sets/inspector/inspector_host_placement_2.dart:4、rep_* の値）は、見本の一覧（inspector_host_gallery.dart:11）にしか出ず、repeater.js とはつながっていない。
