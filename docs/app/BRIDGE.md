# The app-engine bridge

The contract between the Flutter app (`app/`) and the C++ engine (`engine/`, called through `engine/entry/motolii.h`), for anyone who changes either side.

In short: writes are recorded and return at once, questions are answered later, and what changes every frame is subscribed to. The design follows other open-source apps with the same split: Lumit (a bridge contract), AppFlowy (one stream that says what changed and for whom), Rive's CommandQueue (writes are recorded and return, queries arrive later), Anthem (values that change every frame are subscribed to) and Thermion (a draw request is dropped while the previous one runs). Only the ideas of GPL and AGPL projects are borrowed. [`../archive/design/bridge_rework.md`](../archive/design/bridge_rework.md) records the rework that produced this contract.

## Rules

1. **The app never waits for the engine.** No path calls the engine from an app thread and blocks until it answers.
2. **The app never calls the engine inside a widget's `build`.** It reads only the snapshots the engine handed over. Only `app/lib/bridge/`, `main.dart` and the window state (`app/lib/workspace/state/`) hold the engine handle; a panel reads its state. The ast-grep rules `app/tool/rules/import_engine.yml` (import), `import_disk.yml` (`dart:io`/`dart:ffi`) and `engine_only_in_state.yml` (the handle) make this a build break.
3. **There are two snapshots.** The engine's render thread builds each while it holds the project lock, then swaps in the finished object whole. A snapshot is immutable and carries a version number.
   - **Document snapshot** (called "Project snapshot" in earlier code)**.** Built only when the project changes. It holds the list of layers and, for each layer: kind, name, length, key positions, ranges, cards, word choices, how it is shown, the effect list and the resting values. For the whole project it holds markers, guides, the work range, length, size and the list of easings. Each layer has its own version. A layer that did not change is the same object as before, so the app can compare with `identical`.
   - **Time snapshot** (called "Frame snapshot" in earlier code)**.** Built for every frame drawn. It holds the time, the values that are moving, each layer's bounds and visible rectangle, the carried values (`shows`), and for the selected layer whether it has keys, its points and its handles.
4. **The engine reports what changed through one channel.** The channel is a single Dart port: the engine posts to it with Dart's own `Dart_PostCObject` (`NativeApi.postCObject`, `app/lib/bridge/motolii.dart`). A post to a closed port fails safely, so an engine left behind by a hot restart notices its listener is gone and closes itself; a `NativeCallable` of the ended isolate would instead be called freed. The engine says which snapshot is new and, for the project snapshot, the numbers of the layers that changed. The app merges any number of notices within one frame into one.
5. **The app listens only to what it needs.** `WorkspaceController` (`app/lib/workspace/state/workspace_controller.dart`) splits its state into `ValueNotifier`s: the project (whole and per layer), the frame, and the app-only state (playhead, playing, selected layer, selected key, tool panel, shelves, view options, Animate). There is no catch-all `notifyListeners` for the whole controller.
6. **Writes are fire and forget.** A write goes into a queue and returns. A write that needs an id (`add`, `make`) gets its answer later, together with the next snapshot. If the queue already holds a write to the same value of the same layer, the newest one replaces it.
7. **A question about any time but now, or one that takes long, is a query.** The app asks and receives a `Future`. It does not wait inside `build`: when the answer arrives, only the widget that asked is redrawn.
8. **Data read once at start-up** (the folders of recipes, effects and expressions, and the font families) is read once on another thread when the app opens. After that:
   - The user's folder (`~/Library/Application Support/Motolii/`) is watched while the app runs, and its content is read again when a file comes or goes.
   - Every effect on a shelf gets a tile: eight frames of a sample balloon scene (0.1 to 1.9 seconds, played when the pointer is over the tile), rendered in a separate isolate. The engine says where each tile is kept (`~/Library/Caches/Motolii/tiles/`, named by the file and the time it was written; see `doc_tile` in `engine/document/scripts/recipes.cpp`), and the tile is shown at once. The user's files come first. An effect whose result cannot be told from the sample (above 40 dB PSNR, measured with ffmpeg) is marked NO CHANGE. The code is `app/lib/workspace/shelf/effect_tiles.dart`.
9. **The app owns the playhead, the selection and the zoom**, as Lumit does. It tells the engine about them as writes.
10. **A watchdog counts the waits.** `brokenCount` and `broken` in `app/lib/bridge/motolii_watch.dart` report each time the app's thread waited for the engine and each read that waited on the project longer than 2 ms. They also report each take of the snapshots that held the app's thread over its budget (`SnapshotWatch` in `app/lib/bridge/snapshot_watch.dart`): the reads of both snapshots and the listener's own work, each part timed, the first take at opening left out. The count must stay 0.

## What the snapshots contain

Both are JSON, built in `engine/entry/snapshot.h` and read in `app/lib/bridge/`.

- **Document snapshot.** The project-wide part holds the length, size, work range, markers, guides and the list of changed layers, and the tables (the list of easings, the easing curves at 65 points each, the list of effects, the table of default values and the table of values each kind knows). The per-layer part holds the length, the names of values and of values that move, the cards, the effect list, the ranges, the key times, words, resting values, ranges, word choices, how to read the layer, how it is shown, and, for each value, its key times and their easings.
- **Only what differs is handed over.** The engine keeps each snapshot in parts (the members of its JSON object, `engine/base/json_parts.h`), each with the version it last differed at, and the app says which version it has: it is handed the parts newer than that and nothing else, a part that is gone as null. There is no call that hands a snapshot over whole; an app that has none of it yet asks for what is newer than -1. A value dragged hands over that layer's `value` part alone. The tables are made again only for a cause (a table other than `keyframe` changed, the user's own easings did, or the shelf's files did).
- **What was done says what is made again.** The engine takes what each undo step changed from SQLite's own record of it (`doc_note`, `engine/document/undo.cpp`): which values of which layers, and whether more was done to a layer than a number of its set anew (a row put or taken, a word written). A layer that had only numbers set has its numbers alone made again: how long it lasts, its resting values and its keyframes. Its names, cards, words and ranges are made again only when a row was put or taken, a word was written, or a value changed that decides its cards (`motolii_shaping`). Nothing is made whole to find out what changed.
- **The app is told which kind it was.** A read that brought only numbers tells `WorkspaceAspect.document`; one that brought more (a name, a word, a card, a range, a layer come or gone, the document's size or length) tells `WorkspaceAspect.structure` as well. A widget that shows no number of the document listens to `structure` and is left alone while a value is dragged.
- **Reading them.** The app decodes what it is handed from the engine's bytes as they are (`snapshotOf`), puts the parts into the snapshot it holds (`merged`: a snapshot is never changed, only replaced, and with no parts it stays the same object), and parses each part once, on the first read (`parsedOnce`); what was parsed from the parts that did not come is carried along. All three are in `app/lib/bridge/snapshot_parts.dart`. The app also notes which layers a read brought parts of, and whether it brought the list of layers (`layersTaken`, `layerListTaken`): the window's reader (`ProjectReader`, `app/lib/workspace/state/project_reader.dart`) makes again only those layers, and makes its whole list again only when a layer came, went, moved or changed its parent, or the frame rate or length changed. A read costs what changed, not how many layers there are.
- **Time snapshot.** A flat array of numbers, read by the app where the engine keeps it, with no lock and no copy (`motolii_time_numbers`; the render thread fills one of three copies while the app reads another, `engine/base/triple_buffer.h`), for as many layers as there are: the time, then for each layer its bounds, visible rectangle and visible values (x, y, z, rotate, scale_x, scale_y and opacity, and whether a relation moves them; worked out only for the layers the app shows them of: the picked one, the one under the pointer and the watched ones), then the last frame's two times in milliseconds, the render thread's own and the GPU's, which the top bar's load meter shows as parts of a frame's time (`app/lib/workspace/top_bar/load_meter.dart`). And a detail in JSON, handed over only when it differs from the one the app has: for the selected layer and the watched ones their moving values, and for the selected layer its points and handles.
