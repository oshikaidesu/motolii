# 探し方（2026-10-17、ユーザーの承認を得て決めたもの）

**目的**
- 集めるのは、標準の UI に納得できなかったユーザーが、自分で作って置き換えたパネルの UI。たくさん集める。
- 見るのは、パネルが何をするかではなく、画面そのもの。
- 手がかりは、同じものが言語や場所をまたいで、何度も別々に作り直されていること。いいね数、ほめ言葉、新しさは手がかりにしない。

**借りた方法**
- リードユーザー法（von Hippel）：自分で作ってしまった使い手を探す。ピラミッディング（「もっと先を行っているのは誰か」をたどる）と、隣の分野を見ること。
- 多声的文献レビュー（Garousi ほか 2019）：検索の言葉を先に決める。リンクを前後にたどる。飽和したら止める。資料ごとに確かさを点検する。
- 売り場の掘り起こし（Eclipse の売り場の研究）：一覧を端から集める。ダウンロード数を受け入れられた目安にする。「なぜ作ったか」は作者の一言から拾う。

## 手順（機能ごと）

1. **起点**：ui_loved_ja.md、ui_loved_ko_zh.md、ui_loved_en_ru_es_pt.md にある、その機能のパネル。
2. **1本ずつ商品ページを開く**：
   - パネルの画面を自分の目で見て、shots/ に保存する。
   - 作者、日付、使われている証拠（ダウンロード数、レビュー数、まねされた数）を記録する。
   - 「〇〇を参考にした」「〇〇の代わり」「〇〇に似ている」のリンクをたどり、新しいパネルを起点に足す。
3. **隣の分野**：同じ悩みを Nuke、Houdini、ゲームエンジン、音楽ソフトで探す。
4. **止める基準**：新しく開いた3本から新しい形の UI が出なければ、その機能は打ち切る。
5. **記録先**：survey/<機能>.md に1行1本。画面、元の標準の UI の何を置き換えたか、作者、日付、証拠、どこから来たか（どのリンクをたどったか）。

## 順番（標準の UI を置き換えている度合いが強い順）

1. パイメニュー・丸いメニュー
2. ピッカー
3. イージング曲線
4. レイヤーのまとめ（プリコンポーズなし）
5. 整列・配置
6. 輝度マスク
7. 字幕
8. 色
9. 文字の分割

一発で作るもの、ボタン棚は後回し。
