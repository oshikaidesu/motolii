# グループの Inspector — 考え方のメモ（2026-11-05/06）

テキストアニメーション・Cloner・CSS を1つの形にしようとして、2日で辿った筋道と、着地。
次の作業（Flutter の図）を、この会話なしで始められるように。

## 1. 問題

利用者が新しい動きを、開発者を待たずに作れること（AGENTS.md の最初の2行）。

今の Motolii は動き1つが JS（`animators/*.js`）か C++（`doc_place.h` の Wave / Field / Scatter）1本で、
作れるのは開発者だけ。CSS が新プロパティごとに仕様と実装を要るのと同じ構造で、「毎回開発する羽目」になる。

## 2. 共通の形

AE のテキストアニメーター、C4D の Cloner + Effector、CSS のルール、D3 の select().attr()、Houdini の group は
全部同じことをしている：**個々をいじらず、集合にルールを書く**。ルールは「どれに、どれだけ（重み 0〜1）× 何を、
どれだけ（変化）」で、合成は掛け算。種類は閉じる（重み4種、変化3種）。これ以上は要らないし、増やさない。

## 3. 発見：もうあった

これを `weigh.h`（JSON の独自モデル）として書いて動かした後で、リポジトリを読んだら、Motolii には既にあった：

| 文法の部分 | Motolii にあるもの |
|---|---|
| 重み（where） | behaviour（stagger / random / noise）、falloff `region` + `falloff_soft`、`<値>_by` で任意の値に |
| いつ（when） | キー（SQLite の bezier）、`stagger`（`doc_delay`：コピーごとにキーを遅らせる） |
| ease | Godot の easing、interp.h（Alight の9種。Cyclic / Random は揺れ続ける値に）、`ways/*.way` |
| 何を（what） | 物の値そのもの（doc_values、Inspector の行、効果のつまみも `--track@` で行になる） |
| 並び | copies、copy_columns、copy_on（パス沿い）、split letters、MIDI |

`weigh.h` は二重実装だったので消した。**学び：書く前に読む。** 「既存の動作実証を尊重する」はこの意味。

足りなかったのは「順番」の2種だけ（GSAP の `from` にある `random` と `[x, y]`）。`doc_delay` に10行足した。

## 4. UI がコケた理由

UI を1つの問題として扱っていた。分けると5つ：置き場・入口・見た目・編集・確認。
コケたのは「見た目」で、試したものは全部、ルールではなく**結果**（重みの数）を見せていた
（表、文字を塗る、文字を掴む）。それは「個々をいじる」に戻っている。

一方で利用者は仕組み（重み）ではなく結果（文字が順に出る）を触りたい。この矛盾の解き方は、ルールの要素を
**既存の手つきに還元する**こと：

- 何を・どれだけ → 値の行に数を入れる（1つの物と同じ）
- いつ → キーを打つ（同じ）
- 感じ → キーの ease（同じ）
- **どの順で** → ここだけ新しい

新しく覚えるのは1つ。他は1つの物を動かす時と同じ。

## 5. なぜグループの Inspector か：Texton が構造上解けなかったところ

Texton（BOOTH、AE 用の歌詞モーションのパネル）がやっていたのは2つだけ：**文字を区分けする**（1文字ずつレイヤーに）、
**モーションを適用する**（各レイヤーにキー、文字番号 × オフセットでずらし、ease をかける）。つまみは距離・時間・
オフセット・ease に In / Out。よく見ると、これは**分けた文字のための小さな Inspector** で、ease パネルまで持っている。

解けなかったのは AE の構造の側：AE には「派生したメンバーを持つグループ」が無いので、文字を個別に触るには本当に
レイヤーに分けるしかなく、分けた瞬間に文字が打ち直せず、モーションが焼き込まれる。AE 純正のテキストアニメーターは
非破壊だが、UI が属性の木で、Texton はそれを避けて分割を選んだ。

Motolii は構造の側で解ける：グループがメンバーを**派生として**持てる（split letters が既にそう）。だから
Texton の4つまみは全部既存の部品に対応し、パネル自体が要らなくなる：

| Texton | グループの Inspector |
|---|---|
| 1文字ずつレイヤーに分ける（一方通行） | 文字から派生したグループ（文字を直せば追従） |
| 距離 | 値のキーの差（x: 0.3 → 0） |
| 時間 | キーの間隔 |
| オフセット | `stagger`（図を撫でた長さ） |
| ease パネル | キーの ease（既存） |
| In / Out | 始まりと終わりのキー |
| 順番は番号のみ | 図：並び順・点から・ばらばら |
| 文字ごとの効果：レイヤーなので可、ただし手作業 | 効果のつまみも同じ図で配れる |
| 文字専用 | copies でも、選んで作ったグループでも同じ |

Texton が売っていたのは「分けて配る」の手間の省略で、それを構造で持てば、文字を直せる・後から順番を変えられる・
効果も同じ手で配れる・文字以外にも効く、が付いてくる。これが「汎用性が上がる」の中身。
リレーションパネルの話だと思っていたのが、グループの Inspector の話だった、と分かったのはここ。

## 6. 置き場：グループの Inspector

メンバーを持つ物は全部「グループ」。出どころは3つで、Inspector は同じ：

| 出どころ | 派生 |
|---|---|
| 文字を「文字に分ける」 | 非破壊。文字を直せばメンバーが追従（Texton が AE のせいで破壊的だったのはここ） |
| copies を 2 以上 | 元を直せば追従 |
| 複数を選んでグループ | 自由な shape の集まり |

Inspector の構成：上に**並び**（既存の Copies カード：数、間隔、grid、パス沿い、文字）、
各値の行の右端に**配り方の図**。1つの物の時との違いはその図だけ。モードの切り替えは無い。

## 7. 図

24px、ホバーで 72px。メンバーを実際の並びのまま点で並べ、明るさが今の重み。触り方は3つ、他に無い：

| 触り方 | 順番 | 書く値 |
|---|---|---|
| 撫でる | 並びに沿って、撫でた向きに | `stagger_from` = start / end / centre / edges、`stagger`（撫でた長さ＝秒） |
| 押して広げる | その点から外へ | `stagger_from` = point、`stagger_x` `stagger_y`。舞台にも十字 |
| 振る | ばらばら | `stagger_from` = random、`seed` |

ダブルクリックで「全員いっしょ」（stagger 0）。図は**順番だけ**を決める。量（どのコピーがどれだけ動くか）は
並びの側（Wave / Field / Scatter）に残す。Fade In で最後の文字の重みが 0 だと永遠に出ない、という矛盾を
量と順番を1つの図に混ぜた時にコードで踏んだので、分けたまま。

## 9. 今の状態（11/6）

エンジンは済み：`stagger_from` に random と point、`stagger_x` `stagger_y`、stagger のある物はコピーを
1枚ずつ描く、`check/stagger_from.sh` 4項目 yes（Mac）。

次：`skin/book` に図を1枚、新しく書く（`inspector_copies.dart` の流儀を借りる：「絵は結果そのもので、手で引く」、
`Pulled`、`tokens.dart`、`Ctx.of(context).doc`。直すと8割変わるので、1から）。

```
members_drawing.dart（仮、200行ほど）
  読む : copies / copy_x / copy_columns（split の文字なら文字の並び）、stagger、stagger_from、stagger_x、stagger_y、seed
  描く : メンバーを並びのまま点で。明るさ = 遅れの逆（doc_delay の式を Dart に写す。check の数列をテストに）。point なら十字。既存の＋と間隔のつまみ
  触る : 撫でる（向きだけ：stagger_from = start / end / centre / edges、stagger が 0 なら 0.5）、
         押して広げる（point、押した所が stagger_x stagger_y、十字は掴んで動かせる）、
         振る（random、もう一度で seed +1）、ダブルクリック（stagger 0）
  書く : stagger_from、stagger、stagger_x、stagger_y、seed（＋ copies、copy_x）
  下に : 既存の stagger の数字（秒）。キーが無い時は「キーを打つと順に動く」と一行
```

値の行は `PropRow` の `rel` チップで「順に」と出すだけ（stagger は物ごと）。舞台の重み表示と十字はその後。
同じ問題に窓の設計が3つある（`relation_parts` のガジェット15個、`cards_table` の behaviour カード、`inspector_relations`）：
この1枚に合流させ、残りは消す。

## 10. 未決

- 配り方は物ごとに1つ（`stagger` が物の値）。値ごとに分けたくなったら `<値>_stagger` に広げる
- In と Out で逆順にしたい時は別グループに入れ直す（メンバーは shape なので可）
- 単位：`stagger_x` は copies なら舞台の単位、文字なら文字の単位。図の中では正規化するので利用者には見えない
- 効果のつまみを配るには、メンバーが別の物として描かれている必要がある（グループが shape の集まりなら可）

## 11. 進め方

1つずつ。読む → 足す → 本物の舞台で確かめる → 次。飛躍しない。
「全部消せる」「全部できる」と言いたくなったら、1つずつ表にして当てる。
